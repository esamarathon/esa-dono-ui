SETUP WORKFLOW:
================================================================================

Automated Setup (Recommended):
  1. cd /var/lib/ai-workspace/projects/esa/esa-dono-ui
  2. ./tests/e2e/setup-e2e.sh --all
  3. Access http://localhost:8080
  4. Follow tests/e2e/docs/e2e-testing.md test scenarios

Manual Setup:
  1. cd /var/lib/ai-workspace/projects/esa/esa-dono-ui
  2. cp .env.example .env
  3. Edit .env (set ADMIN_API_KEY, build contexts)
  4. git clone https://github.com/esamarathon/kollekt.git ../kollekt
  5. git clone https://github.com/esamarathon/esa-layouts-v2.git ../esa-layouts-v2
  6. docker compose --env-file .env -p esa-dono-e2e -f tests/e2e/docker-compose.e2e.yml --profile with-kollekt --profile with-overlay up -d
  7. cd server && npx prisma migrate dev && npx prisma db seed && cd ..
  8. Access services and run tests

COMMON COMMANDS:
================================================================================

Start services:
  docker compose --env-file .env -p esa-dono-e2e -f tests/e2e/docker-compose.e2e.yml up -d

Stop services:
  docker compose --env-file .env -p esa-dono-e2e -f tests/e2e/docker-compose.e2e.yml down

View logs:
  docker logs -f esa-dono-backend
  docker logs -f esa-rabbitmq
  docker logs -f esa-kollekt
  docker logs -f esa-layouts-v2

Database:
  cd server && npx prisma studio        # Browse database
  cd server && npx prisma migrate reset # Reset database
  cd server && npx prisma db seed       # Seed test data

Clean up:
  docker compose --env-file .env -p esa-dono-e2e -f tests/e2e/docker-compose.e2e.yml down -v  # WARNING: deletes data

Rebuild:
  docker compose --env-file .env -p esa-dono-e2e -f tests/e2e/docker-compose.e2e.yml build --no-cache

TESTING SCENARIOS:
================================================================================

Scenario 1: Full Donation Flow
  Entry point:  http://localhost:8080/admin/simulate
  Flow:         Admin creates donation
                → Backend processes
                → Publishes to RabbitMQ
                → Kollekt consumes
                → Overlay displays
  Verify at:    http://localhost:15672 (RabbitMQ UI)
                docker logs -f esa-kollekt
                http://localhost:3002 (overlay)

Scenario 2: API Integration
  Entry point:  http://localhost:8080/admin (create event, rewards, polls)
  API endpoint: http://localhost:3001/api/admin/tiltify/campaigns/{id}
  Flow:         Kollekt fetches campaign data via REST
                Overlay fetches rewards/polls/goals
  Verify at:    Test endpoints directly via curl

Scenario 3: Message Flow Only
  Skip Kollekt/Overlay
  Monitor:      http://localhost:15672 (RabbitMQ Management UI)
  Verify:       Messages published to correct exchange/queue
